## The Moment Git Made Sense

For a long time, Git felt like a complicated ritual I had to perform before my code was "safe." Push, pull, commit, merge — I did the steps without really understanding what was happening.

Then I broke something badly enough that I needed to go back. And Git saved me. That's when I actually understood what it was for.

## What Git Actually Is

Git is a system that takes snapshots of your code at points in time. Each snapshot is called a commit. You can go back to any commit, see exactly what changed between any two commits, and work on multiple versions of your code at the same time.

That's it. Everything else — branches, merges, remotes — is built on top of that simple idea.

## The Three Commands I Use 90% of the Time

When I'm working on a project, most of my Git usage comes down to three commands:

**git add .** — tells Git which files to include in the next snapshot

**git commit -m "your message here"** — takes the snapshot and labels it

**git push** — sends your snapshots to GitHub so they're backed up and shareable

That's the core loop. Everything else is for more complex situations.

## Understanding Branches

A branch is just a separate line of development. The main branch is where your working, stable code lives.

When I want to try something new without risking breaking my working code, I create a new branch, make the changes there, and only merge it back into main when I'm happy with it.

I'll be honest — when I was starting out I worked entirely on the main branch. That works fine for solo projects. But the habit of using branches becomes important when projects get bigger or when you're working with others.

## The Mistake I Made Early On

I used to write commit messages like "update" or "fix" or "changes." These are useless.

A good commit message tells you exactly what changed and why. Something like "fix mobile nav overflow on 480px breakpoint" or "add fetch logic for posts.json" is something you'll actually thank yourself for six months later.

Write your commit messages for your future self.

## GitHub Is Not Git

This confused me for a while. Git is the version control system that runs on your computer. GitHub is a website that hosts your Git repositories online.

You can use Git without GitHub. GitHub just makes it easy to back up your code, share it, and collaborate with others.

For a developer building a portfolio, GitHub is essential — it's where hiring managers go to look at your actual code.

## The Command That Has Saved Me Multiple Times

```
git log --oneline
```

This shows you a clean list of all your commits. When something breaks and you need to find the last point where everything worked, this is where you start.

## Start Using It Today

If you're not using Git yet, start today. Even on small personal projects. The habit is more important than the complexity of what you're building.

Every professional developer uses version control. Getting comfortable with Git now — before you're in a job — is one of the most practical things you can do to prepare for real work.
